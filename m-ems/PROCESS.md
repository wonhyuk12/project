# M-EMS Strategy API — 작업 기록

보령시 수산업 소상공인 대상 에너지 관리 서비스 'M-EMS' IR 피치덱을 뒷받침하기 위해,
`보령시_수산업_전기예측_한글판.csv` 데이터를 근거로 전기 사용 전략/절감 시뮬레이션/사업성
수치를 자동 생성하는 FastAPI 서버를 만들었습니다.

## 0. 먼저 확인해주세요 — 보안

대화 중에 Gemini API 키(`AQ.Ab8RN6Lv...`)가 평문으로 여러 번 공유됐고, 같은 저장소의
`gemini.ipynb`에도 이전 키가 코드에 그대로 박혀 있었습니다(`git status`상 아직 커밋되진
않았지만 로컬 파일에는 남아 있음). 이번 작업에서는:

- 키를 코드에 넣지 않고 `m-ems/.env`(gitignore 처리됨)에서만 읽도록 구성했습니다.
- `.env`에는 대화에서 주신 키를 넣어뒀습니다(로컬 전용, git 추적 안 됨).

**권장:** Google AI Studio에서 이 키를 한 번 회전(재발급)하시고, `gemini.ipynb`에 하드코딩된
구버전 키들도 지우는 걸 권합니다 — 채팅/노트북에 평문으로 남은 키는 유출 리스크가 있습니다.

## 1. 데이터 해석 및 주의사항

원본 CSV(`data/boryeong_fishery_electricity.csv`, UTF-8로 재저장한 사본)는 실제 스마트미터
실측값이 아니라 **지자체/에너지공단 통계를 근거로 만든 추정(모델링) 값**입니다
(`값의성격` 컬럼이 전부 `추정`). 확인한 특징:

- 2023~2025년 × 9개 업종 세그먼트 = 324행. **연도별로 같은 계절 패턴이 그대로 반복**됩니다
  (2023/2024/2025 연간 합계가 완전히 동일: 총 사용량 77,108,651 kWh, 총 요금 53억 9,761만 원).
  → 아직 "연도별 추세"를 보여주는 데이터는 아니고, "한 해의 계절 패턴을 보여주는 모델"입니다.
- 업종별 개소수(사업장 수)는 연도에 관계없이 고정: 총 131개소(9개 업종 세그먼트).
- 요금 비중 1위는 `C1021 수산물 냉동·냉장업`(9개소, 22.0%, 업체당 월평균 1,100만 원),
  사업장당 부담이 가장 큰 업종이라 M-EMS 초기 실증 타겟으로 가장 설득력이 있습니다.
- 8월이 성수기 피크(계절배수 1.116), 10월이 비수기 저점(0.919)입니다.

IR 발표에서 이 수치를 쓸 때는 "추정 모델 기반"임을 명시하는 게 안전합니다(실제 스마트미터
파일럿 데이터로 나중에 교체 가능하도록 CSV 경로만 바꾸면 되게 설계했습니다).

## 2. 아키텍처

```
m-ems/
  data/boryeong_fishery_electricity.csv   # 원본 CSV의 UTF-8 사본
  app/
    config.py           # .env 로딩, Gemini 키/모델, 경기도 벤치마크 절감률 상수
    data_service.py      # pandas 로딩 + 집계 (업종별/월별/시장규모/절감·매출 시뮬레이션)
    gemini_service.py    # google-genai 클라이언트 + 전략 리포트 프롬프트 빌더
    main.py              # FastAPI 라우트 + 정적 프론트엔드 서빙
  static/
    index.html           # 대시보드 페이지
    style.css             # 스타일(테마 색상 등)
    app.js                 # fetch 호출 + 렌더링 + 마크다운→HTML 변환 (외부 라이브러리 없음)
  requirements.txt
  .env / .env.example
```

- 데이터는 `functools.lru_cache`로 1회만 로드합니다. CSV를 바꾸면 서버를 재시작해야 반영됩니다.
- Gemini 클라이언트는 지연 초기화되며, 키가 없으면 503(`GEMINI_API_KEY가 설정되지 않았습니다`)을
  반환합니다 — 앱 시작 자체는 키 없이도 됩니다.

## 3. 실행 방법

```bash
cd m-ems
pip install -r requirements.txt
# .env.example을 .env로 복사하고 GEMINI_API_KEY 채우기 (이미 .env는 준비돼 있음)
uvicorn app.main:app --reload --port 8000
```

브라우저에서 `http://127.0.0.1:8000` 을 열면 대시보드 웹사이트가 뜹니다.
`/docs`로 가면 Swagger UI로 각 API 엔드포인트를 개별 테스트할 수 있습니다.

## 3-1. 웹 대시보드 (`/`)

발표 데모용 단일 페이지 대시보드입니다. 외부 CDN(폰트/차트 라이브러리 등)을 전혀 쓰지
않아서 **발표장 와이파이가 불안정해도** 로컬에서 그대로 동작합니다.

- **시장 개요 카드**: 총 사업장 수 / 총 사용량 / 총 요금 / 평균 단가 / 1위 업종
- **업종별 요금 비중**: 막대그래프(CSS width 기반, 라이브러리 불필요)
- **월별 계절 패턴**: 1~12월 막대그래프, 피크월(주황)·비수기월(회색) 강조
- **절감 시뮬레이션 계산기**: 도입 사업장 수 / 절감률을 바꿔가며 즉시 재계산
- **구독 매출 시뮬레이션**: 고객 수 구간별 월/연 매출 표
- **AI 전략 리포트 버튼**: Gemini 호출(15~30초) → 마크다운을 카드형 HTML로 렌더링,
  "복사" / ".md 다운로드" 버튼으로 바로 피치덱에 옮겨 쓸 수 있음
- **업종별 딥다이브**: 드롭다운에서 업종 선택 → 해당 업종만의 AI 브리핑 생성
  (`A0331`처럼 코드가 겹치는 업종은 이름까지 함께 넘겨 정확히 구분함)

연도 선택(상단 드롭다운)을 바꾸면 개요/차트가 자동으로 다시 로드됩니다. 절감·매출
계산기와 AI 리포트는 각자의 "계산하기/생성" 버튼을 눌러야 갱신됩니다.

## 4. API 레퍼런스

| Method | Path | 설명|
|---|---|---|
| GET | `/api/health` | 헬스체크 |
| GET | `/api/industries` | 9개 업종 세그먼트 목록(코드/이름/계약종류/개소수) |
| GET | `/api/data?year=&month=&industry_code=` | 원본 행 조회(필터) |
| GET | `/api/summary/industry?year=` | 업종별 총사용량/총요금/비중/업체당 월평균 요금 |
| GET | `/api/summary/monthly?year=` | 월별 총사용량/총요금/계절배수, 피크·비수기월 |
| GET | `/api/summary/market?year=` | 시장 규모 개요(총 사업장 수, 총 사용량/요금, 1위 업종) |
| GET | `/api/summary/savings?year=&industry_code=&usage_reduction_pct=&cost_reduction_pct=&adoption_sites=` | 절감 시뮬레이션(기본값=경기도 실증치 6.2%/4.7%) |
| GET | `/api/summary/revenue?customers=20,50,200,400,1000&monthly_fee=49900` | 구독료 × 고객수 매출 시뮬레이션 |
| GET | `/api/strategy/market?year=&adoption_sites=` | **Gemini**가 생성한 전체 시장 전략 리포트(업종 우선순위/계절전략/IR 카피/로드맵/Q&A) |
| GET | `/api/strategy/industry/{industry_code}?year=` | **Gemini**가 생성한 단일 업종 딥다이브 브리핑 |

`industry_code` 예시: `A0331`(양식업, 2종류 존재), `C1021`(냉동·냉장업), `C1022`(가공·저장),
`A0340`(제빙), `G4631`(위판장·유통) 등 — `/api/industries`로 전체 목록 확인 가능.

### 예시 호출

```bash
curl "http://127.0.0.1:8000/api/summary/savings?year=2025&adoption_sites=20"
curl "http://127.0.0.1:8000/api/strategy/market?year=2025&adoption_sites=20"
```

## 5. Gemini 프롬프트 설계

`app/gemini_service.py`의 `build_market_strategy_prompt()` / `build_industry_deepdive_prompt()`가
프롬프트를 만듭니다. 설계 원칙:

1. **역할 고정**: "충남 서해안 수산업 에너지 컨설턴트 겸 IR 피치덱 자문위원"으로 시스템 컨텍스트를
   고정하고, M-EMS 서비스 개요(타겟 고객, 요금제, 경기도 벤치마크 비교)를 항상 프롬프트에 포함해
   매번 같은 톤/맥락으로 답하게 했습니다.
2. **집계 데이터만 JSON으로 첨부**: 324행 원본 대신 업종별/월별 집계·절감 시뮬레이션 결과만
   압축해서 넣어 토큰을 아끼고, "숫자를 데이터에서만 인용하고 지어내지 말 것"을 명시했습니다.
3. **출력 형식 고정**: 업종별 우선순위 / 계절 전략 / IR 핵심 카피 3개 / 도입 로드맵 / 예상 Q&A
   5개 섹션을 강제해, 결과를 바로 피치덱 초안이나 발표 스크립트에 옮겨 쓸 수 있게 했습니다.

실제 호출 결과(2025년, 20개소 실증 시나리오)로 확인한 품질: 업종별 1~5순위 근거, 8월 피크/10월
저점 계절 전략, IR용 3문장 카피, 3단계 로드맵과 예상 매출, "농사용 전기단가가 낮은데 왜
구독하냐" 류의 날카로운 반론 2개에 대한 데이터 기반 답변까지 모두 생성됨을 확인했습니다.

## 6. 알려진 한계 / 다음 단계

- CSV가 연도별로 동일한 패턴을 반복하므로, "연도 추세"를 물어보는 질문에는 답할 수 없습니다.
  실제 계량 데이터가 쌓이면 `DATA_CSV_PATH`만 바꿔서 교체하면 됩니다.
- 보령시 데이터만 있고 태안군 데이터는 없습니다 — 피치덱의 "보령·태안 합계 4,043어가" 수치는
  이 CSV 밖의 별도 통계(정부 어가 통계)이므로, API의 `total_business_sites`(131개소, 보령시
  전기계약 기준 모델링 수치)와 혼동하지 않도록 발표 시 구분해서 인용하는 게 좋습니다.
- 인증/DB 없이 단일 CSV 기반 읽기 전용 API입니다 — 실제 서비스로 갈 때는 스마트플러그
  실시간 수집(디바이스별 Reading 테이블), 이상 탐지 규칙, 사용자 인증이 별도로 필요합니다.
